# 张家口告家长通知书功能迭代计划

> 任务来源：[张家口告家长通知书功能迭代](https://app.notion.com/p/3bceea1e98c5807ba386efa956370be7) · 任务状态：进行中 · 阶段：方案整理 · 优先级：高

## 一、需求来源与背景

### 现状
机构在组织研学活动时，需要自行撰写《致家长的一封信》发给学生家长，内容包括活动时间、地点、费用、安全须知、注意事项等。当前“告家长书”功能散落在**机构端创建活动**流程中（逻辑与托管活动保持一致，详见 [三方比选流程-新](https://app.notion.com/p/302eea1e98c580b981c0f68c90407784)），并非独立功能单元。

**当前实际实现**：在活动中，用户通过**多行文本编辑框**自定义编辑告家长书内容。**有内容则视为该活动有告家长通知书**，家长在报名时会弹出**电子签名**进行签字；若不填写，则默认没有告家长通知书。当前现状下，**没有明确的功能开关，也没有模板引用逻辑**，内容由机构人员纯手工录入，格式与完整度完全依赖个人。

> 说明：后续迭代引入的"活动创建开关 + 选择模板 + 在线编辑"为目标调整方向，并非当前现状。

### 痛点
- 不同机构、不同运营人员撰写的信件**格式不统一**、内容完整度不一；
- 部分机构可能遗漏关键告知事项（如保险信息、安全预案等），存在**合规风险**；
- 功能耦合在活动创建流程中，维护与扩展成本高。

## 二、迭代目标

1. **重构告家长通知书的功能**，将其作为**独立功能单元**进行维护处理；
2. **构建告家长通知书的完整功能生态**，覆盖模板配置、授权、填写、生成、导出、归档全链路；
3. **引入功能开关与模板引用机制**（目标调整方向）：在活动创建中提供明确的告家长书开关，开启后基于运营后台授权模板在线编辑生成，替代当前纯手工多行文本编辑的方式。

## 三、核心需求拆解

| 需求项 | 说明 | 关键验收点 |
|---|---|---|
| 统一模板 | 模板**不内置**，由**运营后台**配置标准化《致家长的一封信》模板，再**授权给商户**使用，确保机构输出内容格式统一、信息完整 | 运营后台模板配置能力、模板授权机制、关键告知事项（保险/安全预案）必填不可遗漏 |
| 在线填写 | 机构仅需在线填写关键变量信息（活动名称、时间、地点、费用等），其余内容由平台模板自动生成 | 变量字段配置化、预填活动基础信息、生成按钮可触发 |
| 一键导出 | 支持一键导出为可打印的 PDF 或 Word 文档，便于机构线下分发 | PDF/Word 双格式、排版适配打印 |
| 自动归档 | 机构点击“生成文件”后，系统自动将生成的 PDF 文件归档至该活动的“报备材料”模块 | 生成即归档、报备材料可检索 |

## 四、迭代阶段规划

### 阶段一：模板与数据模型重构（基础能力）
**目标**：将告家长书从活动创建流程中解耦，建立独立数据模型，并打通“运营后台配置模板 → 授权商户使用”的链路。

- [ ] 抽离告家长书为独立功能模块，定义独立的数据结构与接口；
- [ ] 重构触发与挂载方式：当前为"多行文本框手工编辑、有内容即挂载"的简单实现，需改造为独立数据模型，并引入功能开关 + 模板引用的目标流程，重新定义告家长通知书数据与活动的挂载关系；
- [ ] 设计标准化模板字段（活动名称、时间、地点、费用、保险信息、安全须知、注意事项等）；
- [ ] 搭建**运营后台**模板配置能力（模板创建、编辑、启用/停用），模板不内置、不预置；
- [ ] 建立**模板授权机制**：运营后台将模板授权给指定商户，商户仅能使用已授权模板；
- [ ] 打通活动基础信息（出行时间、地点、费用、学校/年级等）的自动预填链路。

**交付物**：数据模型设计文档、标准模板字段清单、接口设计文档、运营后台模板配置与授权方案、触发方式解耦方案。

### 阶段二：在线编辑与文件生成能力
**目标**：机构可在线填写变量信息并一键生成《致家长的一封信》。

- [ ] 开发在线填写页面（关键变量字段表单）；
- [ ] 实现模板自动渲染：填写变量 + 商户已授权模板 → 生成完整内容；
- [ ] “生成文件”按钮联调，触发 PDF 生成；
- [ ] 关键告知事项必填校验（保险信息、安全预案等，规避合规风险）；
- [ ] 保留电子签名触发逻辑：活动挂载告家长通知书内容后，家长报名时仍弹出电子签名签字（兼容纯文本与模板生成两种来源）。

**交付物**：在线填写原型/页面、生成逻辑、必填校验规则。

### 阶段三：导出与归档闭环
**目标**：实现一键导出与自动归档，完成文件分发与报备闭环。

- [ ] 支持 PDF 导出，排版适配线下打印分发；
- [ ] 支持 Word 导出，便于机构二次编辑；
- [ ] 生成文件自动归档至对应活动的“报备材料”模块；
- [ ] 报备材料列表支持检索、预览、重新生成。

**交付物**：导出能力、归档逻辑、报备材料联动验证。

### 阶段四：独立功能单元化与生态完善
**目标**：完成重构闭环，构建告家长通知书的完整功能生态。

- [ ] 在机构端/学校端建立独立入口，脱离活动创建流程依赖；
- [ ] 活动创建中引入目标流程的挂载入口：提供明确的告家长书功能开关，开启后走"选择已授权模板 → 在线编辑生成"流程（替代当前多行文本框手工录入）；保留对历史纯文本数据的兼容读取；
- [ ] 与三方比选、集体研学活动详情等既有流程的联动回归验证；
- [ ] 模板版本管理：支持运营后台模板更新与历史版本兼容；
- [ ] 模板授权管理完善：运营后台按商户/区域灵活授权与回收模板，商户端仅展示已授权模板；
- [ ] 权限与可见范围配置（机构/学校/平台分层）；
- [ ] 使用文档与机构端操作指引输出。

**交付物**：独立功能入口、联动回归报告、模板版本管理、模板授权管理、操作指引。

## 六、风险与依赖

- **既有耦合**：当前告家长书为"多行文本框手工编辑、有内容即挂载"的简单实现，内嵌于活动创建流程，解耦与引入开关/模板机制时需保证既有活动链路（含托管活动）不受影响 → 需回归验证。
- **历史数据兼容**：既有活动已通过多行文本框手工录入并挂载了告家长书内容，引入模板化生成与电子签名后，需兼容历史纯文本数据的读取与展示，避免已有活动的告家长书丢失或异常。
- **模板配置与授权**：模板由运营后台配置并授权商户，需明确授权粒度（按商户/区域）、授权变更对商户已生成文件的影响、模板停用回收后的兼容策略。
- **合规要点**：保险信息、安全预案等关键告知事项的必填设计，需产品与业务侧确认最小必填集合，并固化进模板配置。
- **模板维护**：运营后台模板后续可能随政策/项目调整，需预留模板版本管理与历史版本兼容能力。
- **打印适配**：PDF 导出排版需适配线下打印分发场景，需预留打印校验。

## 七、后续动作

1. 本计划确认后，细化阶段一数据模型与字段清单，及运营后台模板配置/授权方案；
2. 与业务侧对齐“关键告知事项”必填集合，并明确模板授权粒度（按商户/区域）；
3. 推动原型设计（运营后台模板配置页 + 商户端在线填写页 + 生成/导出/归档交互）；
4. 评估排期，录入任务列表跟进。
