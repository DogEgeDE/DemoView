# 集体研学活动需求说明

## 1. 需求背景

面向研学机构端，在“研学”业务下提供“集体研学活动”管理能力。机构可查看集体研学活动列表，按条件筛选活动，创建申报活动，编辑活动信息，并在活动审核通过后维护报备材料。

本说明根据当前原型页面整理，原型文件包括：

- `index.html`：集体研学活动列表页
- `form.html`：活动创建/编辑页
- `app.js`：列表数据渲染、创建/编辑模式、编辑风险提示逻辑
- `styles.css`：页面布局、表单、弹窗、分页等视觉状态

## 2. 用户与入口

### 2.1 用户角色

研学机构用户。

### 2.2 功能入口

顶部导航选中“研学”，左侧菜单选中“集体研学活动”，进入集体研学活动列表页。

页面右侧固定展示“机构小程序码”收起入口。

## 3. 集体研学活动列表

### 3.1 页面目标

展示机构已创建或已审核通过的集体研学活动，支持按活动基础条件筛选，并提供查看、编辑、提交、删除、报备材料上传等操作。

### 3.2 筛选条件

列表顶部提供筛选区，字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 适用年级 | 下拉选择 | 默认“请选择”，可选一年级、二年级、三年级等 |
| 活动出行日期 | 日期范围 | 包含开始日期、结束日期 |
| 所属教育局 | 下拉选择 | 默认“请选择”，示例值：吴哥-测试教育局（市级） |
| 学校名称 | 下拉选择 | 默认“请选择”，示例值：吴哥测试小学1（市级） |
| 报名类型 | 下拉选择 | 默认“请选择”，可选“需要报名”“无需报名” |
| 状态 | 下拉选择 | 默认“请选择”，可选“未提交”“已通过” |

筛选区操作：

- 点击“查询”后，按已选择条件刷新列表。
- 点击“展开”后，展示更多筛选条件。原型仅展示入口，更多条件待补充。

### 3.3 保险服务提示

筛选区下方展示“教育保险服务系统”横幅，提示机构及时为被服务学生购买保险。

交互要求：

- 点击“点击进入投保”应跳转或打开教育保险服务系统。
- 跳转地址、打开方式、是否需要单点登录待确认。

### 3.4 列表字段

列表表头字段如下：

| 字段 | 说明 |
| --- | --- |
| 活动名称 | 展示活动封面缩略图与活动名称 |
| 海报二维码 | 有二维码时展示二维码图标，无二维码展示“--” |
| 适用年级 | 展示适用年级，过长时可省略显示 |
| 价格(元) | 展示活动价格 |
| 活动出行日期 | 展示开始日期至结束日期 |
| 报名类型 | 展示“需要报名”或“不需要报名/无需报名” |
| 申报学校 | 展示活动申报学校 |
| 所属教育局 | 展示学校所属教育局 |
| 上/下架 | 开关状态，开表示上架，关表示下架 |
| 状态 | 展示活动当前状态 |
| 审核时间 | 已审核活动展示审核时间，未审核展示“--” |
| 操作 | 根据活动状态展示可执行操作 |

### 3.5 列表操作

每条活动记录支持以下操作：

| 操作 | 适用状态 | 说明 |
| --- | --- | --- |
| 查看 | 全部状态 | 查看活动详情 |
| 编辑 | 全部状态 | 进入活动编辑页 |
| 提交 | 未提交 | 将草稿或未提交活动提交审核 |
| 删除 | 未提交 | 删除未提交活动 |
| 报备材料上传 | 已通过 | 进入报备材料上传流程 |
| 上/下架 | 已通过活动为主 | 控制活动是否对外展示或可报名，具体状态约束待确认 |

### 3.6 分页

列表底部展示分页控件：

- 展示总数，例如“共 76 条数据”。
- 支持页码切换。
- 支持选择每页条数，原型包含“10 条/页”“20 条/页”。
- 支持输入页码并跳转。

## 4. 创建申报活动

### 4.1 入口

在列表页点击“创建申报活动”，进入活动创建页。

页面面包屑为：集体研学活动 / 活动创建。

### 4.2 创建步骤

创建页顶部展示三步流程：

1. 基本信息
2. 选择设置
3. 备案材料

当前原型停留在第 1 步“基本信息”。点击“下一步”后应进入第 2 步，后续步骤内容待补充。

### 4.3 基本信息字段

| 字段 | 类型 | 是否必填 | 原型说明 |
| --- | --- | --- | --- |
| 活动封面 | 上传 | 是 | 点击上传活动封面 |
| 活动名称 | 文本输入 | 是 | 最多 30 个汉字 |
| 价格（元） | 文本/数字输入 | 是 | 输入活动价格 |
| 使用区域 | 下拉选择 | 是 | 默认“请选择” |
| 使用学校 | 下拉选择 | 是 | 默认“请选择” |
| 选择年级 | 下拉选择 | 是 | 可选择多个年级组合 |
| 活动出行日期 | 日期范围 | 是 | 包含开始日期、结束日期 |
| 报名起止时间 | 日期范围 | 否 | 包含开始日期、结束日期 |
| 班级群码 | 上传 | 否 | 上传班级群码图片 |
| 主题类型 | 下拉选择 | 是 | 默认“请选择” |
| 活动目标 | 多行文本 | 否 | 输入活动目标 |

### 4.4 出行人信息收集

创建/编辑活动时可配置出行人信息收集项：

| 信息项 | 默认状态 | 是否可修改 |
| --- | --- | --- |
| 姓名 | 默认勾选 | 不可取消 |
| 手机号 | 默认勾选 | 不可取消 |
| 身份证号 | 默认不勾选 | 可勾选 |
| 监护人身份证号 | 默认不勾选 | 可勾选 |

### 4.5 其他配置

| 配置项 | 类型 | 默认值 | 是否必填 |
| --- | --- | --- | --- |
| 报名类型 | 单选 | 需要报名 | 是 |
| 是否需要勋章 | 单选 | 否 | 是 |
| 是否需要证书 | 单选 | 否 | 是 |

报名类型可选：

- 需要报名
- 不需要报名

是否需要勋章可选：

- 否
- 是

是否需要证书可选：

- 否
- 是

### 4.6 底部操作

页面底部固定操作区包含：

| 操作 | 说明 |
| --- | --- |
| 返回 | 返回列表页 |
| 下一步 | 校验当前步骤必填项，通过后进入下一步 |
| 保存到草稿 | 保存当前活动为草稿或未提交状态，并返回列表页 |

## 5. 活动编辑

### 5.1 入口

在列表页点击活动行中的“编辑”，进入活动编辑页。

页面面包屑为：集体研学活动 / 活动编辑。

### 5.2 编辑数据回显

编辑页应回显活动已有数据。原型示例回显：

- 活动名称：机构集体研学（活动一）
- 价格：0.01
- 年级：一年级,二年级,三年级

### 5.3 编辑风险提示

编辑活动时，如果修改关键字段，需要弹窗提示对已报名学生的影响。

#### 5.3.1 修改价格

触发条件：

- 编辑模式下，价格输入值与原价格不一致。
- 同一次编辑会话中，该提示只弹出一次。

提示文案：

> 修改价格后，已通过原价报名的学生，将会自动退款，请知悉

用户操作：

- 弹窗标题为“提示”。
- 用户点击“我已知悉”后关闭弹窗，继续编辑。
- 用户点击关闭按钮后关闭弹窗，当前原型未阻断编辑。

#### 5.3.2 修改年级

触发条件：

- 编辑模式下，选择年级变更后，新年级范围不再包含全部原年级。
- 同一次编辑会话中，该提示只弹出一次。

示例：

- 原年级为一年级、二年级、三年级。
- 修改后不包含其中任一年级时触发提示。

提示文案：

> 当前修改年级不再包含原年级，原年级已报名学生将会自动退款，请知悉。

用户操作：

- 弹窗标题为“提示”。
- 用户点击“我已知悉”后关闭弹窗，继续编辑。
- 用户点击关闭按钮后关闭弹窗，当前原型未阻断编辑。

## 6. 状态与流程

### 6.1 活动状态

原型中出现的活动状态：

| 状态 | 说明 |
| --- | --- |
| 未提交 | 活动尚未提交审核，可编辑、提交、删除 |
| 已通过 | 活动已审核通过，可编辑、上/下架、上传报备材料 |

### 6.2 创建流程

1. 机构进入“集体研学活动”列表。
2. 点击“创建申报活动”。
3. 填写基本信息。
4. 点击“下一步”进入选择设置。
5. 完成备案材料。
6. 保存草稿或提交审核。

### 6.3 编辑流程

1. 机构在列表点击“编辑”。
2. 系统进入活动编辑页并回显数据。
3. 用户修改字段。
4. 如修改价格或缩小年级范围，系统弹出影响提示。
5. 用户知悉后继续编辑并保存。

### 6.4 已通过活动的报备材料流程

已通过活动列表操作区展示“报备材料上传”。点击后应进入备案材料上传或维护页面。

原型仅展示入口，具体字段与提交流程待补充。

## 7. 校验规则

根据原型必填标识，以下字段或配置必须校验：

- 活动封面
- 活动名称
- 价格（元）
- 使用区域
- 使用学校
- 选择年级
- 活动出行日期
- 主题类型
- 出行人信息收集
- 报名类型
- 是否需要勋章
- 是否需要证书

建议补充校验：

- 活动名称最多 30 个汉字。
- 价格必须为大于等于 0 的有效金额，保留小数位规则待确认。
- 活动出行结束日期不得早于开始日期。
- 报名结束时间不得早于报名开始时间。
- 报名起止时间不应晚于活动出行开始时间，具体规则待确认。
- 上传图片需限制文件类型、大小、尺寸，具体规则待确认。

## 8. 权限与数据范围

原型显示当前用户为“吴哥研学机构（市级）”，列表中学校、教育局与活动数据应受当前机构权限范围控制。

建议规则：

- 机构用户只能查看、创建、编辑本机构权限范围内的活动。
- 学校下拉、教育局下拉、年级选择应根据机构授权范围加载。
- 已通过活动是否允许编辑全部字段，需要结合业务审核规则确认。

## 9. 待确认事项

以下内容原型未完整体现，需业务或产品进一步确认：

1. “选择设置”步骤的字段、规则和页面交互。
2. “备案材料”步骤的字段、附件类型、是否必填、提交规则。
3. 列表“查看”页面的展示内容与可操作项。
4. 活动“提交”后的审核流程、审核角色、状态流转。
5. 已通过活动再次编辑后是否需要重新审核。
6. 已通过活动修改价格、缩小年级范围后，自动退款的触发时机、退款范围、退款失败处理。
7. 上/下架开关的适用状态、是否需要二次确认、是否影响报名。
8. 删除未提交活动是否需要二次确认，是否支持恢复。
9. 教育保险服务系统的跳转地址、登录方式、数据传参。
10. 报名类型为“不需要报名”时，报名起止时间、出行人信息收集项是否仍需展示或校验。
